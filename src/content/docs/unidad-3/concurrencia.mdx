La concurrencia es una característica fundamental de los sistemas operativos modernos.

Permite que varias tareas puedan avanzar durante un mismo periodo de tiempo, aunque no necesariamente se ejecuten exactamente al mismo instante.

Esto ocurre constantemente cuando usamos una computadora.

Por ejemplo:

- Escuchamos música.
- Navegamos por Internet.
- Descargamos archivos.
- Editamos documentos.
- Ejecutamos aplicaciones.
- Copiamos archivos.
- Utilizamos dispositivos externos.

El sistema operativo debe coordinar todas estas actividades para evitar errores.

## 1. ¿Qué es la Concurrencia?

La concurrencia ocurre cuando varios procesos o hilos pueden avanzar durante un mismo periodo de tiempo.

  <h3>🔄 Ejemplo de Concurrencia</h3>

  <div className="u3-flow">

    <div className="u3-arrow">→</div>

En un sistema con un solo núcleo, la CPU puede cambiar rápidamente entre diferentes procesos.

Esto produce la sensación de que todas las tareas se ejecutan simultáneamente.

## 2. Concurrencia y Paralelismo

Aunque estos conceptos están relacionados, no significan exactamente lo mismo.

<div className="u3-grid">

  <div className="u3-card azul">

    <div className="u3-big-icon">🔄</div>

    <h3>Concurrencia</h3>

    <p>
      Varias tareas avanzan durante el mismo periodo de tiempo.
    </p>

    <div className="u3-mini-list">
      <span>Proceso A</span>
      <span>Proceso B</span>
      <span>Proceso C</span>
    </div>

  </div>

  <div className="u3-card verde">

    <div className="u3-big-icon">⚡</div>

    <h3>Paralelismo</h3>

    <p>
      Varias tareas se ejecutan realmente al mismo tiempo utilizando varios núcleos.
    </p>

    <div className="u3-mini-list">
      <span>Núcleo 1 → Proceso A</span>
      <span>Núcleo 2 → Proceso B</span>
      <span>Núcleo 3 → Proceso C</span>
    </div>

  </div>

</div>

### Diferencia principal

| Concurrencia | Paralelismo |
| --- | --- |
| Varias tareas avanzan durante el mismo periodo | Varias tareas se ejecutan al mismo tiempo |
| Puede funcionar con un solo núcleo | Normalmente requiere varios núcleos |
| La CPU cambia entre tareas | Cada núcleo puede ejecutar una tarea |
| Se enfoca en organización | Se enfoca en ejecución simultánea |

El algoritmo de Dekker fue una de las primeras soluciones de software para controlar el acceso a una sección crítica entre dos procesos.

## 12. Algoritmo de Peterson

El algoritmo de Peterson es otra solución clásica para sincronizar dos procesos.

<div className="u3-card azul">

  <h3>⚙️ Elementos de Peterson</h3>

  <div className="u3-grid-3">

    <div className="u3-small-card">
      <span>🚩</span>
      <strong>flag[0]</strong>
      <small>Proceso 0 desea entrar</small>
    </div>

    <div className="u3-small-card">
      <span>🚩</span>
      <strong>flag[1]</strong>
      <small>Proceso 1 desea entrar</small>
    </div>

    <div className="u3-small-card">
      <span>🔁</span>
      <strong>turno</strong>
      <small>Define quién entra primero</small>
    </div>

  </div>

</div>

Cuando un proceso desea entrar:

1. Activa su bandera.
2. Cede el turno al otro proceso.
3. Espera si el otro también quiere entrar.
4. Entra a la sección crítica.
5. Al salir, desactiva su bandera.

### Ventajas

- Es sencillo de comprender.
- Garantiza exclusión mutua.
- Es útil para estudiar sincronización.

### Desventajas

- Funciona principalmente con dos procesos.
- Utiliza espera activa.
- No suele utilizarse directamente en sistemas modernos.

## 13. Mutex

Mutex significa **Mutual Exclusion**.

Es un mecanismo utilizado para bloquear temporalmente un recurso compartido.

<div className="u3-lock-card">

  <div className="u3-lock-icon">🔐</div>

  <h3>Funcionamiento de un Mutex</h3>

  <div className="u3-inline-flow">
    <span className="ok">Mutex Libre</span>
    <b>→</b>
    <span>Proceso A entra</span>
    <b>→</b>
    <span className="wait">Proceso B espera</span>
    <b>→</b>
    <span className="ok">Proceso A libera</span>
  </div>

</div>

Las operaciones más comunes son:

| Operación | Función |
| --- | --- |
| lock() | Bloquea el recurso |
| unlock() | Libera el recurso |

## 28. Sincronización

La sincronización permite controlar el orden de ejecución de varios procesos o hilos.

Su objetivo es evitar:

- Condiciones de carrera.
- Pérdida de datos.
- Acceso simultáneo no controlado.
- Resultados incorrectos.
- Comportamientos impredecibles.

## 29. Inanición

La inanición o **Starvation** ocurre cuando un proceso espera demasiado tiempo por un recurso.

## 30. Interbloqueo

Un interbloqueo o **Deadlock** ocurre cuando varios procesos quedan esperando recursos que están retenidos por otros procesos.

Ninguno puede continuar.

Este tema se estudia con mayor profundidad en la Unidad 4.

## 31. Deadlock vs Starvation

| Deadlock | Starvation |
| --- | --- |
| Varios procesos quedan bloqueados | Un proceso espera demasiado |
| Ninguno puede continuar | Otros procesos sí continúan |
| Existe dependencia circular | Puede ocurrir por prioridades |
| Puede detener parte del sistema | Afecta principalmente a un proceso |

## 41. Preguntas de Repaso

### 1. ¿Qué es la concurrencia?

Es la capacidad de administrar varias tareas que avanzan durante un mismo periodo.

### 2. ¿Qué diferencia existe entre concurrencia y paralelismo?

La concurrencia permite que varias tareas progresen durante el mismo periodo, mientras que el paralelismo permite que varias tareas se ejecuten realmente al mismo tiempo.

### 3. ¿Qué es una sección crítica?

Es una parte del programa donde se utiliza un recurso compartido.

### 4. ¿Qué es exclusión mutua?

Es el mecanismo que permite que solamente un proceso pueda utilizar un recurso crítico en determinado momento.

### 5. ¿Qué es una condición de carrera?

Es un problema donde el resultado depende del orden en que se ejecutan varios procesos.

### 6. ¿Qué es un mutex?

Es un mecanismo utilizado para bloquear y proteger un recurso compartido.

### 7. ¿Qué es un semáforo?

Es una estructura utilizada para controlar el acceso a uno o varios recursos.

### 8. ¿Qué es un monitor?

Es una estructura que organiza datos compartidos y mecanismos de sincronización.

### 9. ¿Qué es IPC?

Es un conjunto de mecanismos que permiten comunicación entre procesos.

### 10. ¿Qué es Deadlock?

Es una situación donde varios procesos quedan bloqueados esperando recursos entre ellos.

### 11. ¿Qué es Starvation?

Es una situación donde un proceso espera durante demasiado tiempo por un recurso.

---

## 42. Conclusión

La concurrencia permite que los sistemas operativos administren varias tareas durante un mismo periodo de tiempo.

Esta capacidad mejora el rendimiento y permite aprovechar mejor los recursos del sistema.

Sin embargo, cuando varios procesos o hilos utilizan recursos compartidos pueden aparecer problemas como condiciones de carrera, interbloqueos e inanición.

Para evitar estos problemas se utilizan mecanismos de sincronización como:

- Mutex.
- Semáforos.
- Monitores.
- Algoritmos de exclusión mutua.
- Operaciones atómicas.

Comprender estos conceptos es fundamental para estudiar sistemas operativos modernos y preparar el estudio de los interbloqueos.
