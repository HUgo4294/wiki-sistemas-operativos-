# Unidad 2 - Definición y Control de Procesos
En esta unidad se estudia uno de los conceptos más importantes de los sistemas operativos: **los procesos**.

Un proceso representa un programa que se encuentra en ejecución y que necesita diferentes recursos del sistema para poder funcionar.

El sistema operativo se encarga de crear, controlar, organizar, suspender y finalizar los procesos. Para realizar estas tareas utiliza diferentes estructuras y mecanismos que permiten administrar de manera eficiente la CPU, la memoria y otros recursos.

Los procesos son fundamentales porque permiten que una computadora pueda realizar varias tareas al mismo tiempo. Por ejemplo, mientras escuchamos música podemos navegar por Internet, escribir un documento y descargar un archivo.

---

## 1. Concepto de Proceso vs. Programa
Aunque los términos **programa** y **proceso** están relacionados, no significan exactamente lo mismo.

### Programa
Un programa es un conjunto de instrucciones que indican a la computadora qué debe hacer.

Es una entidad **pasiva**, porque mientras está almacenado en el disco no está realizando ninguna actividad.

Algunos ejemplos son:

- Un archivo `.exe` de Windows.

- Un programa compilado en Linux.

- Una aplicación instalada en un teléfono.

- Un programa escrito en C, C++, Java o Python.

- Un navegador web.

- Una calculadora.

Podemos imaginar un programa como una **receta de cocina**. La receta contiene las instrucciones, pero por sí sola no está realizando ninguna acción.

### Proceso
Un proceso es un programa que actualmente se encuentra en ejecución.

Cuando el usuario abre una aplicación, el sistema operativo carga la información necesaria en la memoria y crea un proceso.

### Diferencia principal
| Programa | Proceso |

|---|---|

| Es pasivo | Es activo |

| Está almacenado | Está ejecutándose |

| Contiene instrucciones | Ejecuta instrucciones |

| No utiliza CPU mientras no se ejecuta | Utiliza CPU durante su ejecución |

| Puede existir sin ejecutarse | Necesita recursos del sistema |

## 2. ¿Qué necesita un proceso para funcionar?
Para poder ejecutarse, un proceso necesita diferentes recursos proporcionados por el sistema operativo.

Entre los principales recursos se encuentran:

- Tiempo de CPU.

- Memoria RAM.

- Registros del procesador.

- Archivos.

- Dispositivos de entrada y salida.

- Permisos de acceso.

- Información de control.

El sistema operativo administra estos recursos para evitar conflictos entre los diferentes procesos.

## 5. Estado Nuevo
Un proceso se encuentra en estado **Nuevo** cuando acaba de ser creado.

El sistema operativo comienza a preparar los recursos necesarios para su ejecución.

Entre las tareas realizadas se encuentran:

- Crear estructuras de control.

- Asignar un PID.

- Preparar memoria.

- Registrar información del proceso.

---

## 6. Estado Listo
Un proceso está **Listo** cuando puede ejecutarse, pero está esperando que la CPU esté disponible.

## 8. Estado Bloqueado
Un proceso queda **Bloqueado** cuando necesita esperar un evento.

Por ejemplo:

- Lectura de disco.

- Información de red.

- Entrada del teclado.

- Disponibilidad de un recurso.

- Finalización de otra operación.

## 9. Estado Terminado
Un proceso pasa al estado **Terminado** cuando finaliza su ejecución.

Puede ocurrir porque:

- Terminó correctamente.

- El usuario cerró la aplicación.

- Ocurrió un error.

- El sistema operativo lo finalizó.

# 10. Transiciones entre estados
Las principales transiciones son:

<div className="visual-diagram">

                        |

                        ↓

### Nuevo → Listo
El proceso ha sido admitido.

### Listo → Ejecución

### Ejecución → Listo
El proceso pierde temporalmente la CPU.

### Ejecución → Bloqueado
Necesita esperar algún evento.

### Bloqueado → Listo
El evento solicitado terminó.

### Ejecución → Terminado
El proceso finaliza.

# 14. Registros de CPU
Los registros son pequeñas zonas de almacenamiento extremadamente rápidas dentro del procesador.

Pueden almacenar:

- Datos.

- Direcciones.

- Resultados.

- Contadores.

- Información de estado.

La información de los registros debe guardarse cuando un proceso deja la CPU.

# 16. Costo del Cambio de Contexto
Los cambios de contexto son necesarios para la multitarea, pero también consumen recursos.

Durante el cambio:

# 19. Tipos de Planificadores
Existen diferentes niveles de planificación.

| Planificador | Función |

|---|---|

| Largo plazo | Decide qué procesos entran al sistema |

| Mediano plazo | Suspende y reanuda procesos |

| Corto plazo | Decide qué proceso obtiene la CPU |

El planificador de corto plazo trabaja constantemente porque debe seleccionar procesos con mucha frecuencia.

# 20. Planificación de Procesos
La planificación determina cómo se distribuye el tiempo de CPU.

Los algoritmos más conocidos son:

- FCFS.

- SJF.

- SRTF.

- Round Robin.

- Prioridades.

---

# 21. FCFS
**First Come, First Served** significa:

**Primero en llegar, primero en ser atendido.**

Ejemplo:

<div className="visual-diagram">
<pre className="visual-pre">
Llegada:

P1 → P2 → P3

Ejecución:

P1 → P2 → P3
</pre>
</div>

### Ventajas
- Fácil de entender.

- Fácil de implementar.

### Desventajas
- Un proceso largo puede hacer esperar a los demás.

- Puede aumentar el tiempo promedio de espera.

---

# 22. Ejemplo de FCFS
Supongamos:

| Proceso | Llegada | Duración |

|---|---:|---:|

| P1 | 0 | 5 |

| P2 | 1 | 3 |

| P3 | 2 | 2 |

Diagrama de Gantt:

<div className="visual-diagram">
<pre className="visual-pre">
0          5       8      10

|    P1    |  P2   |  P3  |
</pre>
</div>

---

# 23. SJF
**Shortest Job First** selecciona el proceso con menor duración.

Ejemplo:

<div className="visual-diagram">
<pre className="visual-pre">
P1 = 8

P2 = 3

P3 = 5

P4 = 2
</pre>
</div>

Orden:

<div className="visual-diagram">
<pre className="visual-pre">
P4 → P2 → P3 → P1
</pre>
</div>

### Ventaja
Puede disminuir el tiempo promedio de espera.

### Desventaja
Los procesos largos podrían esperar demasiado.

---

# 24. SRTF
**Shortest Remaining Time First** selecciona el proceso con menor tiempo restante.

Es una versión apropiativa de SJF.

<div className="visual-diagram">
<pre className="visual-pre">
P1 ejecutándose

      |

      ↓

Llega P2

      |

      ↓

P2 tiene menor tiempo restante

      |

      ↓

P1 es desalojado

      |

      ↓

P2 utiliza CPU
</pre>
</div>

---

# 25. Round Robin
**Round Robin** distribuye la CPU mediante pequeños intervalos llamados **quantum**.

<div className="visual-diagram">
<pre className="visual-pre">
Quantum = 2

P1 → P2 → P3 → P1 → P2 → P3
</pre>
</div>

Si un proceso no termina durante su quantum, vuelve a la cola de listos.

### Ventajas
- Reparte la CPU.

- Es adecuado para sistemas interactivos.

- Evita que un único proceso monopolice el procesador.

---

# 26. Quantum
El **quantum** es la cantidad máxima de tiempo que un proceso puede utilizar la CPU antes de cederla.

<div className="visual-diagram">
<pre className="visual-pre">
Quantum = 3 ms

P1 → 3 ms

P2 → 3 ms

P3 → 3 ms

P1 → 3 ms
</pre>
</div>

Un quantum demasiado pequeño puede generar muchos cambios de contexto.

Un quantum demasiado grande puede hacer que Round Robin se parezca a FCFS.

# 34. Planificación Apropiativa
En la planificación apropiativa, el sistema operativo puede retirar la CPU a un proceso.

Ejemplos:

- Round Robin.

- SRTF.

- Prioridades apropiativas.

---

# 35. Planificación No Apropiativa
El proceso conserva la CPU hasta que:

- Termina.

- Se bloquea.

- Solicita una operación que requiere esperar.

Ejemplos:

- FCFS.

- SJF no apropiativo.

|---|---|

| Es más independiente | Pertenece a un proceso |

| Crear uno puede ser más costoso | Normalmente es más ligero |

| Puede contener varios hilos | Es una unidad de ejecución |

# 51. Condición de Carrera
Una **Race Condition** ocurre cuando el resultado depende del orden en que varios procesos o hilos modifican información compartida.

Por ejemplo:

<div className="visual-diagram">
<pre className="visual-pre">

Hilo A → suma 5

Hilo B → suma 10
</pre>
</div>

Si ambos modifican el valor al mismo tiempo sin coordinación, puede aparecer un resultado incorrecto.

# 53. Semáforos
Los semáforos son mecanismos de sincronización.

- Controlar acceso a recursos.

- Coordinar procesos.

- Coordinar hilos.

- Evitar determinadas condiciones de carrera.

# 83. Preguntas de Repaso
### 1. ¿Qué es un proceso?
Es un programa que se encuentra en ejecución.

### 2. ¿Cuál es la diferencia entre programa y proceso?
Un programa contiene instrucciones almacenadas y un proceso representa esas instrucciones ejecutándose.

### 3. ¿Qué es el PCB?
Es una estructura utilizada para almacenar información sobre un proceso.

### 4. ¿Qué es un PID?
Es un identificador utilizado para distinguir un proceso.

### 5. ¿Qué hace el Scheduler?
Decide qué proceso utiliza la CPU.

### 6. ¿Qué es un cambio de contexto?
Es el cambio de ejecución de un proceso a otro.

### 7. ¿Qué es un Thread?
Es una unidad de ejecución dentro de un proceso.

### 8. ¿Qué es Round Robin?
Es un algoritmo que reparte CPU utilizando un quantum.

### 9. ¿Qué es una cola de espera?
Es una estructura donde pueden permanecer procesos que esperan algún recurso o evento.

### 10. ¿Qué ocurre con la RAM cuando un proceso termina?
La memoria que utilizaba puede ser liberada y utilizada por otros procesos.

# 87. Resumen de la Unidad
La administración de procesos es una de las funciones más importantes de los sistemas operativos.

Un **programa** es un conjunto de instrucciones almacenadas, mientras que un **proceso** es un programa que se encuentra en ejecución.

Los procesos pueden pasar por estados como:

<div className="visual-diagram">
<pre className="visual-pre">
Nuevo

  ↓

Listo

  ↓

Ejecución

  ↓

Bloqueado

  ↓

Listo

  ↓

Ejecución

  ↓

Terminado
</pre>
</div>

El sistema operativo utiliza el **PCB** para almacenar información importante de cada proceso y el **PID** para identificarlo.

El **Scheduler** decide qué proceso recibe la CPU y el **Dispatcher** se encarga de transferirle el control.

Los algoritmos de planificación como **FCFS, SJF, SRTF, Round Robin y Prioridades** utilizan diferentes estrategias para distribuir el procesador.

Los procesos también necesitan memoria RAM. El sistema operativo debe controlar cuánta memoria utiliza cada proceso y liberar los recursos cuando estos dejan de ser necesarios.

El simulador desarrollado para esta unidad permite observar de forma práctica la creación de procesos, utilización de RAM, duración, progreso, cola de espera y liberación de memoria.

Comprender la administración de procesos permite conocer cómo un sistema operativo organiza los programas que utilizamos diariamente.

Aunque para el usuario parece que diferentes aplicaciones trabajan simultáneamente, el sistema operativo debe administrar constantemente CPU, memoria, estados y otros recursos.

Conceptos como **PCB, PID, estados, hilos, cambio de contexto, planificación, quantum y memoria RAM** son fundamentales para comprender este funcionamiento.

La utilización del simulador permite complementar la teoría mediante una representación interactiva donde se pueden crear procesos y observar cómo cambia el estado del sistema.
